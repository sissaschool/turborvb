2* Lagged Fibonacci pseudo random-number generator
3
4This code implements a lagged Fibonnacci pseudo-random number generator
5with lags p and q in the notation of "A current view of random number generators"
6published by G.A. Marsaglia in Computational Science and Statistics: The Interface,
7ed. L. Balliard (Elsevier, Amsterdam, 1985).
8
9The implementation also relies on the following references:
10
11* P.D. Coddington, "Monte Carlo tests of random number generators", NPAC technical report SCCS-526.
12* P.D. Coddington, "Random number generators for parallel computers." (1997), Syracuse University, SURFACE.
13
14The followings are comments by Paul Coddington in October 1993.
15
16Background
17--------------------
18
19This program implements a lagged Fibonnacci pseudo-random number generator
20using multiplication, with lags p and q, i.e. F(p,q,*) in the notation of
21[Marsaglia].
22
23A sequence of odd random integers Xn is obtained from the formula
24
25Xn= Xn-p * Xn-q mod M
26
27where M is a large integer less than the machine precision (M is taken
28to be 2^{31} here).
29
30Unlike lagged Fibonnacci generators which use subtraction, addition, or
31XOR, this generator seems to give "good" random numbers for ANY lag, not
32necessarily large (see [Coddington]). However larger lags give larger
33periods and empirically seem to give "better" random numbers (see
34[Marsaglia], [Knuth], [Coddington]).
35
36The period is given by (2^{p}-1)*2^{b-3}, where p is the largest lag
37and b is the number of bits in the integers X_{n}, i.e. b = log_{2}(M).
38The lag needs to be chosen large enough to give a period much longer
39than the number of random numbers to be generated.
40
41Only certain lags (p,q) will give the maximal period of the generator
42(see [Marsaglia], [Knuth]). Here are some of those lags, with the
43corresponding periods for 32-bit integers. As a comparison, note that
44linear congruential generators have a period of about 10^{9} (which is
45too short for most purposes), or 10^{18} for 64-bit integers (which is
46fine for most purposes). A Teraflop-year is about 10^{21} floating point
47operations.
48
49P Q period
501279 418 10^{393}
51607 273 10^{191}
52521 168 10^{166}
53250 103 10^{84}
54127 63 10^{46}
5597 33 10^{38}
5689 38 10^{35}
5755 24 10^{25}
5843 22 10^{21}
5931 13 10^{18}
6024 10 10^{16}
6117 5 10^{14}
627 3 10^{11}
635 2 10^{10}
64
65I would recommend using at least (43,22), and ideally (607,273). This
66will only add an extra 607x4 = 2428 bytes to the memory required for
67the user program, which should be completely negligible.
68
69Note that very little is known theoretically about this generator,
70however it performs very well in all empirical statistical tests (see
71[Marsaglia], [Coddington]).
72THIS DOES NOT NECESSARILY MEAN IT WILL PERFORM WELL FOR YOUR APPLICATION.
73It is a good idea to check by using another good generator such as RANF
74or DRAND48 or a good 64-bit generator (see [Coddington]).

76Program
77--------------------
78
79This program is based on the implementation of RANMAR in [James].
80It is the same as RANMAR except it uses multiplication instead of
81subtraction, odd integers instead of reals, and does not include an
82extra Weyl generator.
83
84The program accesses the "lag table", i.e. the array storing the previous
85p values in the sequence, using a "circular list", i.e. the elements of
86the array are not moved with every new addition, only the pointers pt0
87and pt1 to the (n-p)th and (n-q)th value are changed.
88
89NOTE THAT YOU *MUST* CALL THE INITIALIZATION SUBROUTINE (rand_init) BEFORE
90USING THE GENERATOR.
91
92In order for the sequence to be random, the initial values of the lag
93table have to be "random enough". There have not to my knowledge been any
94quantitive tests of this point, however initializing the lag table using
95a good linear congruential generator (the Unix/C generator RAND is used
96here) seems empirically to work fine.
97
98The computation required to generate a new random number, apart from
99updating 2 pointers, is 1 integer multiplication, which multiplies two
10032-bit integers and returns the answer modulo 2^{32} (this is the standard
101for unsigned ints in C), and 1 floating point multiplication, to convert
102the integers into a floating point number in [0,1).
103
104For simplicity and clarity the lag table is indexed from 1 to P rather
105than 0 to P-1.

129#define TWOTO31 2147483648.0
130#define TWOTO30 1073741824
131double TWOTONEG31=(1.0/TWOTO31);
132
133/* Lags, P and Q */
134#define P 1279
135#define Q 418
136
137/* Variables for the lagged Fibonacci generator */
138unsigned int u[P+1];
139int pointer0, pointer1;
140
141/* Variables for the linear congruential generator */
142#define M ( 0x7fffffff ) /* 2^{31}-1 -- mask by M to get modulo 2^{31} */
143#define A 1103515245
144#define K 12345
145
146/***************************************************************************
147 Initialize the lagged Fibonacci random number generator.
148
149 Every bit of all the seeds in the lag table is initialized using the
150 linear congruential generator.
151
152 s = (A * s + K) mod M, where A = 1103515245, K = 12345, and M = 2^{31}-1
153
154 This routine must be called before the random number generator is called.
155***************************************************************************/
156
157/* avoid possible conflict, #ifdef RISC preprocessor */
158#ifdef RISC
159 void rand_init(seed)
160#else
161 void rand_init_(seed)
162#endif
163int * seed;
164{
165 int i,j;
166 int s,t,y;
167
168 y = *seed;
169
170 /* Initialize every bit of the lag table using RAND */
171 for (i=1;i<=P;i++) {
172 s = 0;
173 t = 1;
174 for (j=0;j<32;j++) {
175 y = (A * y + K) & M;
176 if ( y < TWOTO30 ) {
177 s = s + t;
178 }
179 t = t << 1;
180 }
181 /* Seeds must be odd integers because the last bit should be 1 */
182 s = s | 1;
183 u[i] = s;
184 }
185
186 pointer0 = P;
187 pointer1 = Q;
188
189 return;
190}
191
192/***************************************************************************
193 Return a random **double** in [0.0, 1.0).
194
195 !!!Caution!!!
196 Only the most significant 31 bits of drand1 will actually
197 be random, since a random 32-bit integer is converted into a double.
198
199 To return a float instead of a double, simply change the type of rand
200 and drand1 to float.
201***************************************************************************/
202
203/* avoid possible conflict, #ifdef RISC preprocessor */
204#ifdef RISC
205 double drand1()
206#else
207 double drand1_()
208#endif
209{
210 unsigned int unsi;
211 double rand;
212
213 unsi = u[pointer0] * u[pointer1];
214 u[pointer0] = unsi;
215 pointer0 --;
216 if (pointer0 == 0) pointer0 = P;
217 pointer1 --;
218 if (pointer1 == 0) pointer1 = P;
219
220 unsi = unsi >> 1;
221
222 rand = (double)unsi * TWOTONEG31;
223 return(rand);
224}

354 return 1;
