Detailed Description

FFT scalar drivers module for TurboRVB.

This module provides machine-dependent FFT routines for various libraries including FFTW, FFTW3, ESSL, LINUX_ESSL, SCSL, SUNPERF, NEC ASL and ACML. Supports both 3D serial execution and 1D+2D FFTs for parallel execution (except NEC ASL which is 3D only).

Author
TurboRVB group (based on Quantum-ESPRESSO code)
Original authors: Carlo Cavazzoni, P. Giannozzi
Contributors: Martin Hilgemans, Guido Roma, Pascal Thibaudeau, Stephane Lefranc, Nicolas Lacorne, Filippo Spiga
Date
2022 (based on 2001-2008 Quantum-ESPRESSO code)

Features

  • Multiple FFT library support (FFTW, ESSL, etc.)
  • 1D, 2D, and 3D FFT operations
  • Parallel execution support
  • Plan caching for performance optimization
  • Machine-dependent optimizations

Libraries

Supported FFT libraries:

  • FFTW and FFTW3
  • ESSL and LINUX_ESSL
  • SCSL and SUNPERF
  • NEC ASL and ACML

Perform 3D complex FFT.

Driver routine for 3D complex FFT of lengths nx, ny, nz. Uses machine-specific FFT libraries with plan caching for optimal performance. Supports both forward and backward transforms.

Parameters
[in,out]fComplex array to be transformed (in-place)
[in]nxLength of FFT along x-direction
[in]nyLength of FFT along y-direction
[in]nzLength of FFT along z-direction
[in]ldxLeading dimension >= nx (physical x dimension)
[in]ldyLeading dimension >= ny (physical y dimension)
[in]ldzLeading dimension >= nz (physical z dimension)
[in]isignTransform direction: >0 forward (G->R), <0 backward (R->G)
Note
Up to ndims different FFT plans are cached and reused
Forward transform includes normalization factor 1/(nx*ny*nz)
Currently requires ldx=nx, ldy=ny, ldz=nz (not implemented for FFTW)
Uses machine-specific FFT drivers (FFTW, ESSL, etc.)
Plan caching avoids repeated initialization overhead

Perform 3D complex FFT with selective transformation.

Driver routine for 3D complex "reduced" FFT that computes transforms only on lines and planes with non-zero elements. Uses do_fft_x and do_fft_y arrays to specify which transforms to perform (1=perform, 0=skip).

Parameters
[in,out]fComplex array to be transformed (in-place)
[in]nxLength of FFT along x-direction
[in]nyLength of FFT along y-direction
[in]nzLength of FFT along z-direction
[in]ldxLeading dimension >= nx (physical x dimension)
[in]ldyLeading dimension >= ny (physical y dimension)
[in]ldzLeading dimension >= nz (physical z dimension)
[in]isignTransform direction: >0 forward (G->R), <0 backward (R->G)
[in]do_fft_xArray(ldy*nz) specifying which x-lines to transform
[in]do_fft_yArray(nz) specifying which y-planes to transform
Note
Currently implemented for ESSL and FFTW libraries only
Forward transform includes normalization factor 1/(nx*ny*nz)
Requires ny=ldy for current implementation
Uses plan caching for optimal performance
Selective transformation can significantly reduce computation time

Perform 3D complex FFT on box grid for parallel execution.

Driver routine for 3D complex FFTs on box grid in parallel case. FFT along xy is done only on planes corresponding to dense grid planes on the current processor (imin3 <= nz <= imax3).

Parameters
[in,out]fComplex array to be transformed (in-place)
[in]nxLength of FFT along x-direction
[in]nyLength of FFT along y-direction
[in]nzLength of FFT along z-direction
[in]ldxLeading dimension >= nx (physical x dimension)
[in]ldyLeading dimension >= ny (physical y dimension)
[in]ldzLeading dimension >= nz (physical z dimension)
[in]imin3Minimum z-plane index for current processor
[in]imax3Maximum z-plane index for current processor
[in]sgnTransform direction: 1 for f(R) => f(G) only
Note
Currently implemented for ESSL, FFTW, SCSL, COMPLIB libraries
Only supports sgn=1 (forward transform) - backward not implemented
Uses ESSL sign convention (opposite of "usual" convention)
Only transforms planes imin3 <= nz <= imax3 for parallel efficiency
